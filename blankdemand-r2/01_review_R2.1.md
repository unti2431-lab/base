## 0. 한 줄 판정

방향은 맞다. 범위를 좁힌 판단, 성과 표현의 경계, 중단 기준은 그대로 유지한다.
다만 **① 선행연구와 겹치는 정도가 생각보다 크고, ② 데이터 스키마에 대한 가정 일부가 실제와 다르며, ③ 비용·보류·판정 규칙이 숫자로 정의되지 않아** 10/10(토) 구현 단계에서 멈출 수 있다. 아래 P0 7건을 반영하면 4일 안에 계속/축소/중단을 판단할 수 있다.

### P0 — 반영하지 않으면 이번 주 안에 막히거나 심사에서 바로 공격받음

| # | 문제 | 근거 | R2.1 보강 |
|---|---|---|---|

[추정] eval 기간 2024-06-26~07-02 (공개 저장소 기준, 데이터 로드 후 확인) | train 90일 안에서 56/14/20 유지. 공식 eval 7일은 **"외부 공개 검증"**으로 별도 보고(이미 많은 사람이 본 구간이라 잠금 평가로 쓰지 않음). 날짜는 L2가 실제 파일에서 확인 후 `split.json`에 기록 |
| P0-5 | **비용비의 방향과 수식이 없음** — "비용비 0.5·1·2·5, 주 설정 2"만 있음 | — | [제안] r = 부족 단위비용 ÷ 과잉 단위비용. 비용 C(q,d) = c_o·max(q−d,0) + c_u·max(d−q,0). 최적 분위수 τ = r/(1+r) → **r=0.5→0.333, 1→0.5, 2→0.667, 5→0.833**. LightGBM 분위수 회귀의 alpha와 W의 경험분위수를 이 값으로 연결. 정규화 단위이므로 '상대 비용'으로만 보고 |
| P0-6 | **"완전 관측일만 평가"의 선택 편향** — 품절일은 수요가 높은 날에 몰리므로 완전 관측일만 보면 부족 위험이 과소평가됨 | 검열 수요의 일반 성질 | 두 지표를 함께 보고: ① 완전 관측일 상대 비용 ② **품절일 확정 부족 하한** = 품절일엔 d ≥ 판매량 s 이므로 q < s 이면 최소 c_u·(s−q)의 부족이 확정. "관측 하한" 검사를 평가 지표로 승격 |
| P0-7 | **판정·보류 임계값이 숫자로 없음** — 10/10 구현 시 바로 멈추는 지점 | — | §3의 [제안] 규칙표를 v0으로 사용. 검증 구간에서만 조정하고 10/15 잠금. 잠금 전 "보류율–혼합정책 비용 곡선"을 제출물에 포함 |

### P1 — 점수와 완성도를 올림

| # | 보강 | 내용 |
|---|---|---|
| P1-1 | **가상 품절 마스킹을 현실 패턴으로** | 무작위 시간 가리기는 쉬운 문제라 성능이 부풀려짐. 학습 구간의 실제 품절 시작 시각 분포(대부분 오후~마감 연속 구간)를 추정해 같은 모양으로 가린다. 무작위 마스킹 결과는 참고치로만 병기 |
| P1-2 | **B2 정의 구체화** | [제안] 시계열별 시간대 판매 비중 p_h를 학습 구간의 완전 재고일로 추정. 품절일 추정수요 = 재고 정상 시간의 판매 합 ÷ Σp_h(재고 정상 시간). **Σp_h < 0.3이면 '추정 불안정'→보류**, 보정 배수 상한 3배(검증에서 조정) |
| P1-3 | **층화 기준 명시** | [제안] 학습 56일만으로 ① 품절일 비율 3분위 × ② 평균 판매 3분위 = 9층, 비례 추출. 시드·선정 ID·원본 파일 해시 저장. 판매 0 시계열도 제외하지 않고 태그만 붙임(시나리오 B용) |
| P1-4 | **시연 사례 A·B·C 선정 규칙 고정** | 손으로 고른 사례는 체리피킹 의심을 받음. 규칙(예: A=검증 구간, `stock_hour6_22_cnt ≥ 4` & 판매 < 시계열 중앙값)으로 후보를 뽑고 해시 정렬 첫 행을 쓰며, 규칙을 화면에 표시 |
| P1-5 | **분야 결정 규칙** | 10/12 12:00까지 아래 3개가 **모두 서면 확인**될 때만 분석도구 활용 분야로 전환: ① 포털 필수 실행 단계 ② 외부 데이터·로컬 보조 검증 허용 ③ 해당 포털 작업이 10/13~17 사이 6시간 이내. 하나라도 미확인이면 레시피 분야로 잠금. 재검토를 반복하지 않음 |
| P1-6 | **심사 배점 대응표** | 기획성·구체성·실효성·완성도(각 25점)별로 어떤 산출물이 점수를 받는지 §4 표로 연결. 제출 직전 자가 점검표로 재사용 |
| P1-7 | **실효성: 국내 적용 경로** | 국내 효과를 주장하지 않는 대신, 국내 매장이 이 레시피를 쓰려면 **어떤 입력이 최소로 필요한지**(시간대 판매, 품절/진열 기록, 기존 발주량, 포장 단위, 폐기량)를 표로 제시. 운영자 인터뷰 2명은 섭외에 시간이 걸리므로 **이번 주에 요청을 먼저 보냄**(응답 여부와 상관없이 기재) |
| P1-8 | **AI 활용 기록을 처음부터** | 공고문 16쪽 AI 활용 고지 대응. 아래 오케스트레이션의 HANDOFF·RUNLOG가 그대로 'AI 사용 내역' 원장이 되도록 형식 통일 |
| P1-9 | **정본 실행 원칙** | 웹 AI의 파이썬 샌드박스 결과는 초안. **모든 숫자는 로컬 PC에서 재실행한 RUNLOG에서만** 문서로 옮김. 시드·패키지 버전·입력 해시·실행 ID를 함께 기록 |
| P1-10 | **사람 시간의 재배분** | 15시간을 '코드 작성'이 아니라 '실행·검증·판단'에 쓰도록 바꿈. 코드·조사·문서 초안은 ChatGPT 레인이 병렬로 만들고, 사람은 통합·실행·관문 판단만 한다(§5, `02_orchestration_plan.md`) |

### P2 — 여유가 있을 때

- 공식 eval 7일 결과를 공개 저장소의 보고치와 형식만 대조(수치 비교 주장 금지, 평가 설정이 다름).
- 모델 교체 대비: 사용하는 웹 AI 모델이 기간 중 바뀔 수 있으므로(예: 10/14 일부 모델 종료 공지) 프롬프트·계약은 채팅 기억이 아니라 **파일**로 유지.
- 영상: 이번 주는 R2대로 **실제 도구 화면 녹화만** 한다. 설명용 인서트가 필요하면 10/15 잠금 이후 **Google Flow 단독 파이프라인**으로 15초 이내, "개념 설명" 표기, 수치·결과 화면은 생성하지 않음(실제 결과는 반드시 녹화본).

## 3. 판정·보류 규칙 v0 [제안]

> 10/10 구현용 초기값. 검증 구간(14일)에서만 조정, 10/15 잠금. 잠금 평가 20일에서는 바꾸지 않는다.

| 순서 | 규칙 ID | 조건 | 판정 | 행에 남길 근거 |
|---|---|---|---|---|
| 1 | E1 | 필수 필드 누락, 음수 판매, 24시간 배열 길이 ≠ 24 | 입력 오류 | 필드명·행 ID·위반 규칙 |
| 2 | E2 | 판단 시점 이후 정보가 특성에 포함(타임스탬프 > 발주 시점) | 입력 오류 | 혼입 필드·시각 |
| 3 | E3 | 일 판매 합 ≠ 시간대 판매 합(허용오차 밖) | 입력 오류 | 두 값·차이 |
| 4 | H1 | 최근 14일 중 완전 관측일 < 3 | 추천 보류 | 완전 관측일 수·다음 확인 행동 |
| 5 | H2 | B2 보정에서 Σp_h < 0.3 또는 보정 배수 > 상한 | 추천 보류 | Σp_h·배수 |
| 6 | H3 | 예측 분산 지표 (P90−P10)/중앙값 > k (k는 검증에서 결정, 초기 1.5) | 추천 보류 | 구간·k |
| 7 | M1 | 대안의 기대 상대비용이 기존안보다 δ 이상 낮음(초기 δ=5%) **그리고** 잔차 부트스트랩 200회 중 ≥ 80%에서 대안이 우세 | 수정 검토 | 기존안·대안·τ·비용 차·우세 비율 |
| 8 | K0 | 위 어디에도 해당 없음 | 기존안 유지 | 유지 근거·미검사 항목 |

- **정상 0 보존(R1)**: 재고 정상 시간이 영업창 전부이고 판매 0이면 보정하지 않음 — 위반 시 시험 실패로 처리(판정 아님).
- **관측 하한(R2)**: 품절일에 대안 q < 관측 판매 s 이면 "확정 부족" 경고를 근거 열에 표시.
- 기존안이 없으면 B0(전주 동요일)를 기존안으로 쓰고, 화면에 "기준규칙 기존안"으로 표시.
