# GAP28 R4a — 실사 선별 작업 폴더

계획서: `../GAP28_R4_REVISION_PLAN.md` §2.5 (선별 프로토콜), §2.2–2.3 (전환 A·B), §11 (사용자 할 일)

## 흐름
1. 사용자 PC: 촬영본 폴더에서 `python make_r4a_proxies.py` (드라이브 `보강작업/make_r4a_proxies.py`) → `R4a_proxies/proxy_*.mp4`, `sheet_*.jpg`, `r4a_live_manifest.json`
2. 드라이브 `보강작업/R4a_proxies/` 에 업로드 (파일당 10 MiB 미만이면 클라우드에서 직접 내려받는다)
3. 클라우드: `python3 -I analyze_proxies.py <R4a_proxies> --out <R4a_proxies>/r4a_metrics`
   - `r4a_live_metrics.json` 클립별 노출·흔들림·삼각대 판정·슬롯별 후보 창 3개
   - `contact_<clip>.jpg` 타임코드·밝기·흔들림이 찍힌 30칸 콘택트 시트
4. 후보 창을 육안 판독해 `LIVE_SELECT.md` 작성: L1–L4 In/Out 프레임, 전환 B 방식(삼각대 → 디졸브 / 핸드헬드 → 노이즈 전사), 재질 레퍼런스 스틸 5장

## make_r4a_proxies.py 검토 (2026-10-24)
- 컴파일·명령 구성 정상. 회전 메타(−90°)는 ffmpeg 자동 회전이라 `scale=270:480` 이 맞다. bt709 행렬 명시, 30fps, 모노 48k 오디오(앰비언스 이음 확인용) 유지.
- 비트레이트 상한 220 kbps 는 선별용으로 충분하나 **전환 컷의 솔브·광류 판정에는 부족**하다. 선별이 끝나면 채택 창(±1초)만 540×960 crf 22 로 한 번 더 뽑는다(각 2–4 MB).
- 시트에 타임코드가 없다(`drawtext` 는 Windows 폰트 경로 문제로 뺀 것으로 보임). 셀 i 의 시각 = i × (길이/24). 클라우드의 `analyze_proxies.py` 가 타임코드 시트를 다시 만들므로 그대로 둬도 된다.

## 측정값 해석
- `motion_px` 는 위상상관 전역 이동량을 1080 기준 px/F 로 환산한 값이다. 창 평균 < 0.5 → 삼각대, < 1.5 → 전환 컷 허용(핸드헬드), 그 이상 → 전환 컷 부적합(본편 중간 슬롯은 가능).
- `luma` 는 중앙 70% 평균(0–255). STYLE 명도 기준 75–135.
- `dark_tail_pct` 는 창 마지막 24F 의 어두운 화소 비율. L2 후보는 이 값이 올라가야(틈 속 하강) 전환 A 와 이어진다.
- 점수는 보기 순서다. 채택은 시트·프록시 육안 판독으로만 한다.
