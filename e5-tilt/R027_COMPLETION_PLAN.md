# E5 「작은 기울임의 원리」 — R027 완성 계획 (R026c 인수)

작성 2026-10-29 · 인수자 Claude · 근거: `R027_intake/` (CCL 원문, 해시, 씬 조사 JSON, 실제 렌더 2장)

## 0. 결론

R026c는 실제 E5 노즈·도색과 공기스프링 접촉부를 크게 개선했다. 그러나 레퍼런스급까지 남은 격차는 **세 덩어리**다.

1. **대차와 중간차가 여전히 R025 프록시**다. 레퍼런스(Bf 109)의 설득력은 정밀한 히어로 기구에서 나오는데, 우리 히어로 기구가 박스 수준이다.
2. **측면 차체에 셰이더 결함 2건**이 있다. 실제 창 위에 가짜 창 사각형이 겹치고, 투시 창과 근접 보조광이 흰 번짐을 만든다.
3. **동작량(평균 6.49, 목표 9)·사운드·자막·실시청 게이트가 열려 있다.**

R027은 이 셋을 8개 라운드로 닫는다. 장면 편집·검증·270p/540p 검수는 내가 클라우드에서 끝까지 수행한다. 540p 전편과 1080p 최종 렌더는 사용자 GPU에서 스크립트 한 번으로 돌리고, 1× 실시청 승인은 사용자가 한다.

## 4. 지키는 잠금 (CCL에서 승계)

- 구매 에셋과 실차 OEM CAD는 쓰지 않는다. 대차는 "일반화된 설명용 대차"로 자체 제작한다.
- 기존 운동과 최대 1.5°를 바꾸지 않는다. 판독 문제는 각도 과장이나 검사 기준 하향으로 풀지 않는다.
- 3D 씬 안에 글자·숫자·로고를 넣지 않는다. 글자는 자막 레이어에서만.
- 양측 동시 급·배기 화살표는 넣지 않는다(E5 실차 제어로 미확인). 높이차 표시만 쓴다.
- 좌우 높이차 약 5 cm는 모형값이다. 화면·내레이션에 수치로 쓰지 않는다.
- R026c 동결 마스터와 원본은 수정하지 않는다. R027은 REVIEW 사본에서 새 버전 파일로 저장한다.
- 모든 장면 수정은 재실행 가능한 스크립트(`r027_*.py`)로 하고, 변경 전후 해시와 로그를 남긴다.

## 5. 라운드 계획

한 라운드는 한 작업군만 바꾸고, 끝날 때마다 G4와 해당 게이트를 다시 통과시킨다. 각 라운드 산출물은 `review/R027x/`에 새로 만들고 덮어쓰지 않는다.

### R027-0 기준선 (반나절)
- REVIEW 사본을 `E5TILT_R027_base.blend`로 고정하고 해시를 기록한다.
- 블렌드에서 모든 애니메이션 변환을 프레임별로 추출하는 `extract_motion.py`를 만든다. 이것이 R027 내내 "리그 보존" 비교 기준이다(R026 NPZ 없이도 검증 가능).
- R025 `verify_scene.py`를 R026 씬에 그대로 돌려 기준값을 다시 잰다.
- 270p 전편을 렌더해 동작량을 내 측정법으로 다시 잰다. CCL의 6.49와 측정 조건이 같은지 확인한다.

### R027a 결함 수리
- `BODY_01/10`의 재질에서 R025 창 마스크 경로를 끊고, 원본 메시의 창 면(`r026_livery` 속성)만 유리로 쓴다.
- 히어로 차량 창은 "카메라가 안에 있을 때만 투시"로 바꾼다(Backfacing + Is Camera Ray). 외부에서는 어두운 유리.
- `LIGHT_NEAR_01`은 대차 근접 컷에서만 켜고, 빛 연결(light linking)로 데크 바닥을 제외한다.
- 통과 조건: 540p F30·F650·F700에서 결함 0, G4 PASS.

### R027b 중간차 8량 교체
- 선두차 원본 메시의 정단면 구간(노즈 뒤 일정 단면)을 잘라 25 m 중간차를 만든다. 창·출입문 간격은 원본 메시 패턴을 반복한다.
- 8량은 같은 메시를 공유하는 인스턴스로 둔다. 연결부(갱웨이) 형상도 원본 비례로 교체한다.
- 기존 `BODY_02~09`의 위치·회전 키는 그대로 쓰고 메시만 바꾼다.
- 통과 조건: C01·C08·C09 270p에서 프록시 흔적 0, 차체 간 간섭 0.

### R027c 히어로 대차 재모델 (최대 작업)
- 대상: `BOGIE_01_R` 아래 부품과 ISO 사본. 오브젝트 이름·피벗·부모를 그대로 유지해 리그와 검사가 바뀌지 않게 한다.
- 부품 목록(일반형 볼스터리스 대차): 용접 측면 프레임(리브·플랜지·용접 비드), 가로빔, 축상과 베어링 커버 볼트, 1차 코일 스프링 2열, 축상 링크(모노링크), 차륜(웹·림·답면 테이퍼), 차륜 디스크 브레이크와 캘리퍼, 기어박스와 커플링, 견인 전동기(냉각 핀), 요댐퍼(로드 엔드), 좌우 댐퍼, 안티롤바, 견인 링크, 공기스프링(다중 주름 벨로우즈·상하 비드판·비상 고무 스프링), 높이조절밸브와 레버·링크, 공기 배관(곡선 스윕).
- 예산: 6만–12만 삼각형, 30° 이상 모서리 베벨을 메시에 굽는다.
- 벨로우즈는 셰이프키 11개 인터페이스를 그대로 다시 만든다. `stroke`는 h_min→h_max, `plate_*` 9개는 상단 링 정점의 단위 변위로 만들고, R026의 키 가중치 커브를 그대로 옮긴다. 그래서 공극 0.20 mm 거동이 보존된다.
- 높이조절밸브 레버는 차체–대차 상대 높이로 회전각을 베이크해 실제로 움직이게 한다(관절 기구 하나 추가).
- 통과 조건: G4 PASS(교차 0), 상판 공극 0.15–0.25 mm, 540p C03 F200·C05 F345 스틸.

### R027d 표면·환경
- 대차 재질: 도장 프레임(진회색, 모서리 마모로 금속 노출), 축상·기어박스 기름때, 차륜 답면 연마·브레이크 분진, 볼트 헤드 범프. 모두 절차 노드라 외부 이미지가 없다.
- 궤도: 레일 체결구(0.625 m 간격 인스턴스), 슬래브 이음매 실링, 케이블 트로프. 근접 추종 컷에서 속도감과 프레임 차이를 함께 만든다.
- 고가교: 방음벽 패널 이음·얼룩, 데크 배수구.
- 전차선: 전주·빔·급전선·조가선·트롤리선. 선 굵기는 540p에서 1 px 이상이 되게 한다.
- 원경: 저폴리 수목 산포, 원거리 구릉, 송전탑. C09 크레인과 객실 창밖에 시차를 만든다.
- 스커트: 패널 라인과 점검구.
- 통과 조건: 재질 ROI ≥ 0.3, 2 Mbps 스트레스본에서 체결구·이음매 깜박임 없음.

### R027e 카메라·사건·강조 (동작량 처방)

| 컷 | 현재 문제 | 처방 |
|---|---|---|
| C04·C06 객실 | 컵과 등받이만 보여 정지에 가까움 | 창을 프레임 한쪽에 넣어 수목·전주·방음벽이 통과하게 하고, 컵→창→컵 초점 이동을 사건으로 둔다 |
| C07 정면 1.5° | 열차와 카메라가 같이 움직여 정지에 가까움 | 전차선 포털이 머리 위로 주기적으로 지나가게 하고, 아주 느린 푸시를 둔다. 각도·형상은 그대로 |
| C02·C05 | 이미 양호 | 부품 강조 틴트만 추가 |
| C03 ISO | 양호 | 분해 순서를 명사 발화 순서에 맞춘다 |
| C09 | 원경 구간이 단조로움 | 원경 수목·구릉 시차로 해결(R027d) |

- 부품 강조: 레퍼런스처럼 설명 중인 부품만 한 색(라임 계열 반투명 틴트)으로 칠한다. 명사 발화 6F 전에 켜고 문장 끝에서 끈다. STYLE의 "한 색 한 의미"에 강조색으로 등록한다.
- 미세 차량 진동(레일 이음 주기의 1–2 px)은 선택 사항이다. 지표만 올리는 장치가 되지 않도록 사용자 승인 후에만 넣는다.
- 통과 조건: 동작량 평균 ≥ 9, 모든 1초 ≥ 3, W0 일치, 루프 SSIM ≥ 0.85.

### R027f 사운드
- 효과음을 전부 자체 합성한다(라이선스 문제 없음): 통과 굉음, 레일 이음 타격(실제 차륜 통과 시각에서 계산), 공기 흐름음(스프링 스트로크 속도에 비례, 밸브 방향은 주장하지 않음), 분해 클릭, 바람, 객실 룸톤, 전환 우쉬.
- 큐는 블렌드에서 추출한 사건 프레임으로 만든다(±1F).
- 믹스: VO 우선 덕킹, −14 LUFS·−1 dBTP, C09 꼬리를 C01 굉음에 크로스페이드해 루프 이음을 맞춘다.

### R027g 자막
- `basak-shorts-caption` 스킬의 R08 규격으로 한 줄 자막을 입힌다.
- VO 원문 텍스트와 단어 시각이 필요하다. R026의 `VO_WORDS_R026.json`을 받으면 그것을 쓰고, 없으면 사용자가 대본 텍스트를 주어야 한다(클라우드에서는 음성인식 모델 다운로드가 막혀 있다).
- 1.5° 같은 숫자는 C07 자막에서만 쓴다.

### R027h 검수와 납품
1. 클라우드: 라운드마다 270p 전편 + 변경 컷 540p 스틸 2장 + 컨택트 시트.
2. 클라우드: 핵심 4초(C05 + C07 앞부분) 540p 32spp.
3. 사용자 GPU: `RUN_R027.ps1 -Stage preview`로 540p 전편 → 사용자 1× 휴대폰 시청 → 수정 목록.
4. 수정 반영 뒤 사용자 GPU에서 `-Stage final` 1080p → 믹스·자막 합성 → delivery_qc → RELEASE_CHECK.md.
